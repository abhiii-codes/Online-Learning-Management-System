Academic Context

Problem Statement & Educational Motivation

The Educational Problem

  • • Fragmented Systems: Course management, materials, student submissions, and grading are often dispersed across disparate tools, causing high friction for faculty and learners.
  • • Security & Privacy Gaps: Students must never see peers' grades, instructors must not modify other instructors' courses, and public users cannot elevate permissions.
  • • Manual Assessment Friction: Faculty spend valuable time manually grading multiple-choice questions without instant automated feedback.

The Engineering Solution

  • • Strictly Grounded Engineering: Implemented without Spring Boot or ORM (Hibernate) so students genuinely master the fundamental socket, servlet, and JDBC mechanisms.
  • • Decoupled 4-Tier Architecture: Clear separation between React presentation, Jakarta Servlet controllers, Service business rules, and JDBC DAOs.
  • • Enterprise Standards: Complete 3NF relational normalization, 100% PreparedStatements, explicit JDBC transactions, and BCrypt security.

System Design

4-Tier Decoupled Layered Architecture

TIER 1: PRESENTATION TIER Browser / Client
React 18 + TypeScript + Tailwind CSS SPA

Single-page interface with tailored dashboards for Students, Instructors, and Admins. Includes an Evaluator Demo Bar for instant 1-click persona switching.

TIER 2: SERVLET CONTROLLER TIER Apache Tomcat 10.1 (Port 8080)
Jakarta Servlets 6.0 & BaseServlet Base Class

14 Servlet endpoints handling RESTful HTTP verbs (doGet, doPost, doPut, doDelete). Centralized JSON dispatch and error translation with CorsFilter and SecurityUtils session guards.

TIER 3: BUSINESS SERVICE TIER Pure Java Interfaces & AppContext
13 Domain Services & Explicit JDBC Transaction Demarcation

Enforces business policies (duplicate enrollment checks, instructor course ownership, grade bounds). Demarcates ACID boundaries using direct JDBC setAutoCommit(false), commit(), and rollback().

TIER 4: DATA ACCESS & STORAGE TIER HikariCP 5.1 & MySQL 8.x / Embedded H2
11 JDBC DAOs & 14 Relational Tables (3NF Normalized)

100% Parameterized PreparedStatements for SQL injection immunity. Try-with-resources resource cleanup. Automatic failover to embedded H2 for zero-config evaluation.

Core Java Concepts Implementation

1. Encapsulation & Composition

• All model properties are private with validated public getters/setters.
• Domain composition mirrors real entities: Course contains Modules; Module contains Lessons; Course contains Assignments and Quizzes.

2. Inheritance & User Hierarchy

• Abstract base class User contains shared authentication and profile state.
• Specialized subclasses: StudentUser (studentId, major), InstructorUser (department), and AdminUser (adminLevel).

3. Runtime Polymorphism & Strategy

• Subclasses override abstract methods getRoleDashboardUrl() and hasAdministrativePrivileges().
• Strategy pattern via GradingStrategy interface (StandardGradingStrategy vs WeightedGradingStrategy).

4. Generics, Interfaces & Exceptions

• 11 DAO and 13 Service interfaces completely decouple contracts from storage.
• Custom LmsException hierarchy mapped centrally to HTTP status codes.
• Strict type-safe collections with generics: List<Course>, Map<String, Object>, Optional<T>.

Direct Database Integration (JDBC 4.x)

PreparedStatement & Resource Safety

  • 100% PreparedStatements: All SQL queries bind dynamic values via positional placeholders (?). Dynamic string concatenation is completely barred, ensuring 100% SQL injection immunity.
  • Try-With-Resources: Every database operation employs AutoCloseable try blocks, ensuring connections, statements, and result sets are released even if exceptions occur.
  • HikariCP Connection Pool: Maintains a high-throughput connection pool with sub-millisecond acquisition latency.
  • Generated Key Retrieval: Using Statement.RETURN_GENERATED_KEYS to bind child rows immediately without secondary lookups.

Deadlock-Free ACID Transactions

// TransactionManager Helper (Eliminates FK Deadlock)
TransactionManager.execute(conn -> {
  // 1. X-Lock FIRST + Capacity Enforcement
  courseDao.incrementEnrolledCount(conn, courseId);
  // 2. Child Insert under Parent X-Lock
  enrollmentDao.enroll(conn, enrollment);
  return enrollment;
});
// 3. Post-commit best-effort notification
notificationService.sendNotification(...);

Verified through automated test ServiceTransactionTest.java (Capacity check, rollback suppression, and drop).
